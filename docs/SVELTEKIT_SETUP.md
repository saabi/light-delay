# SvelteKit 2 / Svelte 5 setup

> **Documento histórico de bootstrap.** El scaffold ya fue completado y varias instrucciones siguientes describen decisiones deliberadamente temporales. El estado vigente usa `@sveltejs/adapter-static`, prerender, GitHub Pages y Paraglide; consultar `docs/PROJECT_STATUS.md` y `README.md` antes de aplicar cualquier paso de este documento. La mención de `adapter-auto` en la sección 9 no es una instrucción actual.

This document covers project bootstrap only. It deliberately does not define the full content migration, JSON extraction process, final routes, visual system or editor architecture. Those decisions belong in the later migration plan.

## Goals

- Create a minimal SvelteKit 2 / Svelte 5 application at the repository root.
- Use TypeScript in strict mode.
- Preserve `docs/`, `data/` and `legacy-site/` unchanged.
- Establish formatting, linting, unit tests and browser tests before migration.
- Keep deployment decisions reversible.
- Avoid introducing UI frameworks or application state libraries during setup.

## Prerequisites

- Git.
- Git LFS.
- A current supported Node.js LTS release.
- npm, using the lockfile committed to the repository.

Verify the local tools:

```bash
node --version
npm --version
git --version
git lfs version
```

Record the selected Node version in `.nvmrc` or an equivalent version-manager file after the scaffold is created. Do not commit `node_modules/`.

## 1. Protect the existing handoff

Start from a clean Git working tree:

```bash
git status
git add .
git commit -m "chore: preserve pre-Svelte project handoff"
git lfs install
```

Confirm that the following already exist and must survive scaffolding:

```text
AGENTS.md
README.md
docs/
data/
legacy-site/
```

Do not run a scaffold command over uncommitted files.

## 2. Scaffold outside the repository root

The repository root is not empty. Create the minimal application in a temporary sibling directory instead of bypassing the CLI directory-safety check:

```bash
cd ..
npx sv create --template minimal --types ts --add eslint prettier vitest playwright --install npm light-delay-svelte-bootstrap
```

The official `sv create` command supports the `minimal` template, TypeScript and multiple add-ons. The temporary directory prevents the generator from overwriting project documents.

Do not select Tailwind, Storybook, authentication, databases, internationalization or experimental add-ons during bootstrap. They can be evaluated during migration planning.

## 3. Copy the scaffold into the repository

Copy only the generated application files into the repository root. Preserve existing project-owned files when names overlap.

Expected additions include:

```text
src/
static/
tests/
package.json
package-lock.json
svelte.config.js
vite.config.ts
tsconfig.json
eslint.config.js
.prettierrc
.prettierignore
playwright.config.ts
```

Exact generated filenames may vary with the current CLI. Treat the scaffold produced by `sv create` as authoritative rather than manufacturing missing configuration from an older example.

Before copying a generated `.gitignore`, merge it with the repository's existing `.gitignore`. Do not replace `.gitattributes`, because it contains the Git LFS media rules.

After copying, remove the temporary scaffold directory only after the application passes all validation commands.

## 4. Preserve the initial directory boundaries

The initial application should follow this shape:

```text
.
|-- src/
|   |-- lib/
|   |   |-- components/
|   |   |-- data/
|   |   |-- types/
|   |   |-- utils/
|   |   `-- server/
|   `-- routes/
|-- static/
|   `-- assets/
|-- tests/
|-- data/
|-- docs/
|-- legacy-site/
`-- package.json
```

During setup:

- `src/lib/components/` may remain empty except for a README or placeholder.
- `src/lib/data/` will eventually load and validate canonical JSON.
- `src/lib/types/` will eventually contain the definitions described in `docs/JSON_FORMAT.md`.
- `data/` remains the source-controlled canonical content area.
- `static/assets/` is the eventual public asset destination.
- `legacy-site/` remains untouched as the regression reference.

Do not move the existing images into `static/assets/` during bootstrap. Asset migration requires a mapping and reference validation step.

## 5. Minimal application shell

Keep the generated landing page deliberately simple. It needs only to prove that routing, styling and builds work. Do not begin recreating the document index or animatic yet.

The first setup commit should contain:

- a root layout;
- a minimal root page identifying the project;
- global baseline CSS;
- one trivial component test;
- one Playwright smoke test confirming that `/` loads.

Use Svelte 5 syntax for new components. Do not add compatibility patterns for legacy Svelte unless a real dependency requires them.

## 6. TypeScript and aliases

Retain the TypeScript configuration generated by SvelteKit. SvelteKit generates and extends `.svelte-kit/tsconfig.json`; avoid replacing that relationship with a standalone configuration.

Use the built-in `$lib` alias for application code:

```ts
import type { ScriptFile } from '$lib/types/script';
```

Do not add aliases for `data/` until the migration plan decides whether JSON will be imported at build time, copied into `static/`, or loaded through server modules.

## 7. Package scripts

Keep the standard generated scripts and ensure there are commands equivalent to:

```json
{
  "scripts": {
    "dev": "vite dev",
    "build": "vite build",
    "preview": "vite preview",
    "check": "svelte-kit sync && svelte-check --tsconfig ./tsconfig.json",
    "lint": "prettier --check . && eslint .",
    "format": "prettier --write .",
    "test:unit": "vitest run",
    "test:e2e": "playwright test",
    "test": "npm run test:unit && npm run test:e2e"
  }
}
```

Prefer the generated script definitions when they differ only mechanically. Do not pin commands to an obsolete scaffold.

## 8. Static assets and Git LFS

The existing `.gitattributes` tracks common image, video and audio formats with Git LFS. Verify tracking before adding migrated assets:

```bash
git lfs track
git check-attr filter -- legacy-site/assets/animatic/frames/scene-01/shot-01.png
```

The second command should report `filter: lfs`.

Do not duplicate all existing assets into `static/` until the migration plan defines canonical paths. Temporary duplication would approximately double repository storage.

## 9. Adapter and rendering mode

Keep `adapter-auto` during setup. The deployment target has not been selected, and SvelteKit allows the adapter to be changed later without redesigning routes.

Do not globally disable SSR or force static prerendering during bootstrap. The document viewer may ultimately be prerendered, while editing or export functionality may benefit from other rendering modes. Decide that during migration planning.

## 10. Validation gate

Before committing the scaffold, run:

```bash
npm run format
npm run lint
npm run check
npm run test:unit
npm run test:e2e
npm run build
npm run preview
```

Manually verify:

- `/` renders without console errors;
- direct navigation and reload work;
- no files under `docs/`, `data/` or `legacy-site/` were deleted;
- `legacy-site/index.html` still opens independently;
- all 100 existing animatic frames remain present;
- PNG files are handled by Git LFS;
- no generated build output or dependencies are staged.

## 11. Initial commits

Keep setup separate from migration:

```text
chore: scaffold SvelteKit 2 application
test: add initial unit and browser smoke tests
docs: record validated SvelteKit setup
```

Do not combine JSON extraction, visual redesign or script rewriting with the scaffold commit. A clean setup baseline makes later migration changes reviewable and reversible.

## Setup completion criteria

Setup is complete when:

- the minimal SvelteKit application runs locally;
- linting, type checking, unit tests, browser tests and production build pass;
- the legacy package is intact;
- Git LFS is active;
- no narrative content has been migrated or modified;
- the repository is ready for the separate migration-planning phase.
